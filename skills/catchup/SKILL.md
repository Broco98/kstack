# catchup

독자는 **잠깐 자리를 비웠다 돌아온 사용자**다. 목표는 두 가지를 바로 알게 하는 것이다. **지금 내가 무엇을 정해야 하나**, 그리고 **나에게 무엇이 바뀌었나**.

## 이 턴은 읽기 전용이다

보고 읽기만 한다. 코드와 문서를 고치지 않고, 작업이나 subagent를 띄우지 않고, 커밋 · push도 하지 않는다. 기다리는 결정은 추천까지만 하고, 실행은 사용자가 답한 뒤에 한다.

## 모으기

1. **기준점을 정한다.** 인자로 범위를 받았으면 그것이다. 없으면 **사용자가 보낸 마지막 메시지**다.
2. **기준점 뒤에 생긴 것을 모은다.**
   - 대화: 에이전트의 중간 보고, 알림, subagent 결과, 도구 출력
   - 저장소: `git status`, `git log --oneline`(기준점 뒤의 커밋), 바뀐 파일의 `git diff --stat`
   - 작업: 아직 도는 작업, 끝난 작업, 실패한 작업
   - 기다리는 것: 사용자의 답이 있어야 다음으로 갈 수 있는 자리
3. 모은 것을 `## 형식`대로 쓴다.

## 형식

이 절은 `kstack:implement`의 마지막 보고도 따른다. 그때 기준점은 구현을 맡긴 사용자의 메시지다.

**전제: 사용자는 자기가 보낸 마지막 메시지까지만 기억한다.** 그 뒤에 지나간 것은 모두 처음 듣는다고 본다. 알림과 subagent 결과는 사용자의 메시지가 아니다. 그래서 앞서 중간 보고로 말한 것도 다시 말하고, 그 사이에 새로 지은 이름이나 줄임말에 기대지 않는다.

순서는 이렇다.

### 1. 첫 문장 — 기다리는 결정

«지금 결정을 기다리는 것이 <개수>개 있어요.» 없으면 «지금 기다리는 결정은 없어요.» **첫 문장에는 이것만 쓴다.**

### 2. 결정마다 추천 · 근거 · 위험

```markdown
**결정 1 — <무엇을 정해야 하나>**
- 추천: <하나를 고른다>
- 근거: <왜. 사용자가 확인할 수 있는 사실로>
- 위험: <추천대로 했을 때 잘못될 수 있는 것. 낮으면 «낮음»과 그 이유>
```

- «예»라고만 답해도 추천을 받아들이는 뜻이 되게 쓴다.
- 위험이 낮아도 «낮음»이라고 적는다. 칸을 비우지 않는다.

### 3. 바뀐 것 — 사용자에게 무엇이 달라졌나

**어떻게 했는지가 아니라 결과를 쓴다.** 띄운 작업, 거친 단계, 쓴 도구 대신 사용자가 보고 겪을 변화를 쓴다. 사용자의 말로 쓴다.

| 과정을 말한 것 | 바뀐 것을 말한 것 |
|---|---|
| subagent 셋이 worktree에서 구현하고 merge했다 | 로그인을 여러 번 틀리면 계정이 잠겨요 |
| CI green | 테스트 통과 |
| `AuthService`를 리팩터링했다 | 로그인 동작은 그대로예요. 로그인 코드가 한 파일로 모였어요 |

### 4. 그림 — 필요할 때만

바뀐 것의 모양이 글보다 그림으로 빨리 읽힐 때만 그린다.

- **상자는 6개 이하, 상자 하나에 8단어 이하.**
- 상자는 `[ ]`로 감싼다. 낱말은 띄어쓰기로 센다.
- 코드 블록 안에 ASCII로 그린다.
- 상태 목록(완료 · 진행 · 대기)은 그림 대신 목록으로 쓴다.

```
[로그인 요청] ──→ [실패 횟수 확인] ──→ [잠금 또는 통과]
```

### 5. 아직 안 끝난 것

도는 작업과 막힌 것을 한 줄씩 적는다. 없으면 이 항목을 뺀다.

---

- **숫자는 도구 출력에서 읽은 것만 쓴다.** 테스트 수 · 파일 수 · 줄 수를 세지 않았으면 숫자 없이 쓴다.
- 전체를 짧게 쓴다. 사용자가 더 물으면 그때 자세히 간다.
- 말투는 해요체다.

### 점검 — 세어서 0

- **① 기다리는 결정(또는 «없어요»)으로 시작하지 않은 답 0**
- **② 추천 · 근거 · 위험 가운데 하나라도 빠진 결정 0**
- **③ 과정만 말하고 사용자에게 바뀐 것이 없는 줄 0**
- **④ 도구 출력에서 읽지 않은 숫자 0**
- **⑤ 6개를 넘는 상자, 8단어를 넘는 상자 0**
