# MISSION.md 형식

`MISSION.md`는 작업 공간 루트에 둔다. 사용자가 이 주제를 배우는 _이유_를 담는다. 모든 가르침의 결정(다음에 무엇을 가르칠지, 어떤 자료를 내놓을지, 어떤 연습을 설계할지)은 이 문서까지 거슬러 올라가야 한다.

## 템플릿

```md
# Mission: {Topic}

## Why
{1-3문장. 사용자가 쫓는 구체적인 현실의 목표. 이 기술을 갖추면 삶이나 일에서 무엇이 달라지는가? "X를 이해하려고" 같은 추상적 틀은 피하고, 밑바탕의 결과를 끌어낸다.}

## Success looks like
- {사용자가 할 수 있게 될, 구체적으로 관찰 가능한 일}
- {또 다른 구체적인 일}
- {…}

## Constraints
- {시간, 예산, 선약, 학습 선호 등 접근법을 제약하는 모든 것}

## Out of scope
- {사용자가 지금은 쫓고 싶지 않다고 분명히 한 인접 주제. 근접발달영역을 지킨다}
```

## 규칙

- **작업 공간마다 미션 하나.** 사용자가 서로 무관한 두 가지를 배우고 싶다면 작업 공간이 둘이다.
- **추상보다 구체.** "10월까지 하프 마라톤 완주"가 "더 건강해지기"보다 낫다. "팀에 Rust CLI 출시"가 "Rust 배우기"보다 낫다.
- **모호함에 맞선다.** 사용자가 이유를 말하지 못하면 무엇을 쓰기 전에 먼저 인터뷰한다. 나쁜 미션은 미션이 없는 것보다 나쁘다.
- **현실이 바뀌면 고친다.** 미션은 바뀐다. 사용자의 목표가 움직이면 이 파일을 갱신한다. 낡은 미션이 이후 세션을 이끌게 두지 않는다.
- **짧게 유지한다.** `MISSION.md`가 한 화면을 넘으면 나침반이 아니라 계획이 되기 시작한 것이다.
