# 증거 사다리

**동작에 관한 사실**을 얼마나 세게 증명했는지 재는 기준이다. «이 함수는 빈 배열을 돌려준다», «이 변경은 캐시 항목만 지운다» 같은 사실이 여기에 든다. 동작은 돌려 보면 드러나므로 **실행할수록 단계가 오른다.**

**의도에 관한 사실**(«왜 이렇게 만들었나»)은 이 사다리로 재지 않는다. 아무리 실행해도 이유는 증명되지 않는다. 그쪽은 같은 폴더의 `confidence-tiers.md`를 따른다. 두 기준을 한 딱지로 섞지 않는다.

사실을 찾고 사다리를 올리는 일은 **에이전트 몫**이다. 사람에게 넘기는 것은 결정뿐이다.

## 다섯 단계

| 단계 | 이름 | 한 일 | 예 |
|---|---|---|---|
| ① | 주장 | 말로만 했다. 근거를 보이지 않았다 | «`getItems`는 장바구니가 비면 빈 배열을 돌려준다» |
| ② | 위치 | 그 동작을 하는 코드의 `file:line`을 짚었다 | «`src/cart.ts:42`에서 `items`가 없으면 `[]`를 돌려준다» |
| ③ | 추적 | 입력에서 결과까지, 특히 **실패하는 경로**를 한 단계씩 따라갔다. 지나는 자리마다 `file:line`을 이었다 | «`null` 장바구니 → `loadCart`(`src/cart.ts:12`) → `getItems`의 가드(`src/cart.ts:42`) → `[]`. 예외로 빠지는 길은 없다» |
| ④ | 실행 | 그 동작을 실제로 돌렸다. 테스트 · 스크립트 · REPL · CLI. 명령과 출력이 있다 | «`node --test test/cart.test.mjs` → `empty cart returns []` 통과» |
| ⑤ | 재현 | 실행 중인 앱에서, 사용자가 보는 자리에서 재현했다 | «개발 서버에서 빈 장바구니 페이지를 열어 "담긴 상품이 없습니다"가 뜨는 것을 봤다» |

- 단계는 **한 일**로만 오른다. 확신이 커져도 한 일이 같으면 단계도 같다.
- ④는 **주장한 바로 그 동작을 돌린 것**이다. 빌드 · 타입체크 · 린트 통과는 «빌드된다»의 ④일 뿐, «빈 배열을 돌려준다»의 ④가 아니다.
- ⑤는 화면이나 앱 전체 동작이 걸린 사실에 쓴다. 앱을 띄워 볼 때는 Claude Code 내장 `run` 스킬을 쓴다.
- **남이 돌렸다는 말은 단계를 올리지 않는다.** subagent가 «테스트 통과»라고 보고했으면 그것은 ①이다. 출력을 직접 보거나 명령을 다시 돌려야 ④가 된다.

## 어디까지 올렸는지 밝힌다

동작에 관한 사실을 적을 때마다 단계를 함께 적는다. 꼴은 이렇다.

```
<사실> — 사다리 ②: src/cart.ts:42
<사실> — 사다리 ③: loadCart (src/cart.ts:12) → getItems (src/cart.ts:42) → []
<사실> — 사다리 ④: `node --test test/cart.test.mjs` → 1 passed
<사실> — 사다리 ①: 확인 못 함 (<더 올리지 못한 이유>)
```

- **단계 표시가 없는 동작 사실은 0이어야 한다.**
- 필요한 단계까지 못 올렸으면 **멈춘 단계를 그대로 적고 이유를 붙인다.** 이유의 예: 실행 환경이 없다, 외부 서비스가 필요하다, 그 데이터는 운영에만 있다.
- 출력 요약은 출력에 있던 것만 옮긴다. 숫자도 출력에서 읽은 것만 쓴다.

## 어디서 몇 단계가 필요한가

| 쓰는 곳 | 무엇 | 최소 단계 |
|---|---|---|
| `kstack:how` | 동작 흐름의 단정 | ② |
| `kstack:spec` | one-way 결정을 받치는 사실 (`door.md`) | ④ |
| `kstack:tickets` | 수용 기준마다 붙이는 증명 명령 | ④. 화면이 바뀌면 ⑤ |
| `kstack:implement` | «완료» 보고 | ④. 티켓의 증명 명령을 돌린 출력 |
| `kstack:inspect` | Correctness 지적 | ④. 지적마다 재현 명령 · 그 출력 · 의도가 요구하는 출력. 돌려 보지 못한 것은 «의심» 목록에 따로 둔다 |
| `kstack:pr` | Evidence | ④ 이상. `kstack:tickets`의 증명 명령을 구현 전후로 돌린 출력 |

더 높이 올릴 수 있으면 올려도 된다. 표의 단계는 바닥이다.

## 안전을 받치는 단 하나의 사실

위험해 보이는 변경도 대부분은 **사실 하나** 덕분에 안전하다. 그 사실이 참이면 안전하고, 거짓이면 사고가 난다. 그 사실을 찾아 **④까지** 올린다. one-way 결정(`door.md`)과 `kstack:pr`의 Blast Radius 칸이 이것을 쓴다.

1. **무엇이 깨질 수 있나**를 한 줄로 쓴다.
2. **그런데도 안전하다고 믿는 이유**를 사실 한 문장으로 줄인다. 거짓일 수도 있는 문장이어야 한다. «아마 괜찮다»는 사실이 아니다.
3. **그 사실이 거짓이라면 무엇이 보일지** 먼저 적는다. 그다음 그것을 보는 명령을 돌린다.
4. 결과를 위 «어디까지 올렸는지» 꼴로 적는다.
5. **거짓으로 드러나면 그 변경은 안전하지 않다.** 진행하지 않고 사람에게 보고한다. 어떻게 할지는 결정이고, 결정은 사람 몫이다.

| 변경 | 깨질 수 있는 것 | 받치는 사실 | 거짓이면 보일 것 → 증명 |
|---|---|---|---|
| 세션 저장소를 메모리에서 Redis로 옮긴다 | 배포하는 순간 로그인한 사용자가 모두 로그아웃된다 | 세션 토큰은 서명으로 검증되고, 저장소를 읽지 않는다 | 옛 판에서 받은 토큰으로 새 판에 요청하면 401이 난다 → 실제로 요청해 200을 본다 (④) |
