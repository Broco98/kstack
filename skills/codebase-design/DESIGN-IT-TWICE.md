# Design It Twice

선택한 deepening 후보에 대해 사용자가 대안 인터페이스를 탐색하고 싶어 할 때 이 병렬 sub-agent 패턴을 쓴다. "Design It Twice"(Ousterhout)에 바탕을 둔다. 첫 아이디어가 최선일 가능성은 낮다.

[SKILL.md](SKILL.md)의 어휘(**module**, **interface**, **seam**, **adapter**, **leverage**)를 쓴다.

## 과정

### 1. 문제 공간을 틀 짓는다

sub-agent를 띄우기 전에, 선택한 후보의 문제 공간을 사용자에게 보여 줄 설명으로 쓴다.

- 새 인터페이스가 만족해야 할 제약
- 그것이 기댈 의존성과, 그 의존성이 속하는 범주([DEEPENING.md](DEEPENING.md) 참고)
- 제약을 구체적으로 보이게 하는 대략적인 예시 코드 스케치. 제안이 아니라 제약을 구체화하는 수단일 뿐이다

이것을 사용자에게 보여 주고, 곧바로 2단계로 간다. sub-agent가 병렬로 일하는 동안 사용자가 읽고 생각한다.

### 2. sub-agent를 띄운다

sub-agent 3개 이상을 병렬로 띄운다. 각각 deepening된 모듈에 대해 **근본적으로 다른** 인터페이스를 내야 한다.

각 sub-agent에게 별도의 기술 브리프(파일 경로, 결합 세부, [DEEPENING.md](DEEPENING.md)의 의존성 범주, seam 뒤에 무엇이 있는지)를 주어 프롬프트한다. 브리프는 1단계의 사용자용 문제 공간 설명과 별개다. 에이전트마다 다른 설계 제약을 준다.

- Agent 1: "인터페이스를 최소화한다. 진입점은 최대 1~3개. 진입점당 leverage를 최대화한다."
- Agent 2: "유연성을 최대화한다. 많은 사용 사례와 확장을 지원한다."
- Agent 3: "가장 흔한 호출자에 맞춰 최적화한다. 기본 경우를 사소하게 만든다."
- Agent 4 (해당하면): "seam을 가로지르는 의존성은 ports & adapters로 설계한다."

각 sub-agent가 아키텍처 언어와 프로젝트의 도메인 언어에 맞게 일관되게 이름을 붙이도록, 브리프에 [SKILL.md](SKILL.md)의 어휘와 GLOSSARY.md의 어휘를 모두 넣는다.

각 sub-agent의 산출물:

1. 인터페이스 (타입, 메서드, 파라미터, 그리고 불변식, 순서, 에러 모드)
2. 호출자가 어떻게 쓰는지 보여 주는 사용 예
3. 구현이 seam 뒤에 숨기는 것
4. 의존성 전략과 adapter ([DEEPENING.md](DEEPENING.md) 참고)
5. 트레이드오프: leverage가 높은 곳, 얇은 곳

### 3. 보여 주고 비교한다

사용자가 하나씩 소화할 수 있도록 설계를 차례로 보여 준 다음, 산문으로 비교한다. **depth**(인터페이스에서의 leverage), **locality**(변경이 모이는 곳), **seam 위치**로 대조한다.

비교한 뒤에는 어느 설계가 가장 강하고 왜 그런지 자기 추천을 준다. 서로 다른 설계의 요소를 합치면 좋을 때는 하이브리드를 제안한다. 단호하게 말한다. 사용자가 원하는 것은 메뉴가 아니라 강한 판단이다.
