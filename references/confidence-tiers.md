# 확신도 다섯 단계

**의도에 관한 사실**을 얼마나 믿을 수 있는지 매기는 기준이다. «왜 이렇게 만들었나», «왜 Y를 골랐나», «이 상한은 무엇을 지키려나» 같은 진술이 여기에 든다.

의도는 **기록으로만** 단계가 오른다. 코드는 무엇을 하는지만 보여 주고, 왜 있는지는 보여 주지 않는다. 그래서 실행해도 단계가 오르지 않는다. 동작에 관한 사실은 같은 폴더의 `evidence-ladder.md`를 따른다.

두 기준을 한 딱지로 묶으면 «PR 본문에 그렇게 적혀 있다»와 «커밋 흐름상 그래 보인다»가 같은 무게로 읽힌다. 이해를 돕는다면서 틀린 확신을 심게 된다. **틀린 이해는 이해가 없는 것보다 비싸다.**

## 다섯 단계

| 단계 | 뜻 | 딱지에 함께 적는 것 | 딱지 예 |
|---|---|---|---|
| **직접** | 누군가 그 이유를 글로 남겼다. PR 본문 · 리뷰 · 커밋 메시지 · 코드 주석 · 티켓 · ADR · spec에 남은 사용자의 말 | 그 글의 인용과 자리 | `(직접: PR #812 본문 «<그 글의 문장 그대로>»)` |
| **수렴** | 서로 독립인 간접 근거 여럿이 같은 결론을 가리킨다 | 근거 목록 | `(수렴: 커밋 a1b2c3d 메시지 · 같은 커밋에 생긴 재시도 코드 src/pay.ts:30 · 이슈 #40 제목)` |
| **추론** | 맥락상 그럴듯하지만 뒷받침하는 기록이 없다 | 근거로 삼은 맥락 | `(추론: 바로 위 함수도 같은 상한을 쓴다)` |
| **추측** | 다른 설명도 똑같이 들어맞는다 | 경쟁하는 설명과, 무엇이 그 둘을 가를지 | `(추측: 성능 때문일 수도, 외부 API 제한 때문일 수도 있다. 결제사 API 문서가 가른다)` |
| **모름** | 찾아봤지만 없다 | 어디를 어떤 말로 찾았는지 | `(모름: git log -S "100" · PR 본문 · docs/ 에서 "limit" 검색, 없음)` |

## 쓰는 규칙

1. **의도에 관한 진술마다 딱지 하나.** 딱지 없는 의도 진술은 0이어야 한다.
2. **확신 표현은 직접 단계에서만 쓴다.** «~때문이다», «~하려고 설계됐다», «~를 막으려고 넣었다», «의도는 ~다» 같은 말은 **인용이 바로 옆에 있을 때만** 쓴다. 다른 단계는 그 단계에 맞는 말을 쓴다.

   | 단계 | 쓰는 말 |
   |---|---|
   | 직접 | «~때문이다» + 바로 옆에 인용 |
   | 수렴 | «~때문으로 보인다. 근거 여럿이 같은 쪽을 가리킨다» |
   | 추론 | «~일 수 있다. 뒷받침하는 기록은 없다» |
   | 추측 | «A일 수도, B일 수도 있다» |
   | 모름 | «이유를 찾지 못했다» + 찾아본 자리 |

3. **사람의 결정은 원래 말을 인용한다.** 누가 · 언제 · 어디에 남겼는지와 함께 그 말을 글자 그대로 옮긴다. 에이전트의 해석은 줄을 바꿔 따로 두고, 해석에도 딱지를 붙인다. 인용 부호 안에는 원문만 둔다. 줄이거나 다듬은 말은 인용 부호 밖에서 해석으로 쓴다.

   ```
   - 사용자 (2026-03-02, docs/adr/0007-queue.md): «<원래 말 그대로>»
     해석 (추론): <에이전트가 읽은 뜻>
   ```

4. **동작에서 의도로 건너뛰면 추론이다.** «코드가 X를 한다»(사다리로 증명한 사실)에서 «그러니 X를 하려고 만들었다»로 넘어가는 순간, 근거는 기록이 아니라 맥락이 된다. 따로 남은 기록이 없으면 추론 이하다.
5. **모름도 결과다.** 찾아본 자리와 찾은 말을 남긴다. 다음 사람이 같은 곳을 다시 뒤지지 않게 한다.
