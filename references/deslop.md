# deslop — 군더더기 걷어 내기

slop(군더더기)은 에이전트가 쓴 코드에 흔히 남는 찌꺼기다. 동작은 하지만 읽는 사람의 부담을 늘리고, 주변 코드와 어긋난다. deslop은 «완료»를 말하기 전에 **이번 diff가 더한 줄**에서 그것을 걷어 내는 일이다.

- **언제**: `kstack:implement`의 구현자가 티켓의 증명 명령을 돌린 뒤, «완료»를 보고하기 전.
- **범위**: 이번 diff가 더하거나 고친 줄. 원래 있던 코드는 그대로 둔다.
- **동작은 바꾸지 않는다.** 걷어 낸 뒤 증명 명령을 다시 돌려 통과를 확인한다(`evidence-ladder.md` ④).

## 체크리스트

### 1. 쓸데없는 주석

- **모습**: 코드를 말로 다시 읽는 주석(`// count를 1 늘린다`), 작업 과정을 적은 주석(`// 새로 추가`, `// 여기를 고쳤다`, `// 예전 방식 대신`), 지운 코드를 설명하는 주석.
- **시험**: 지워도 읽는 사람이 잃는 것이 없나.
- **할 일**: 지운다. 코드만 보고는 알 수 없는 **이유**는 한 줄로 남긴다.

### 2. 신뢰 경로의 과한 방어 코드

- **모습**: 타입이나 앞 단계가 이미 보장한 값에 다시 하는 `null` 검사, 실패할 리 없는 내부 호출을 감싼 `try`/`catch`, 에러를 잡아서 삼키거나 로그만 찍고 넘기는 `catch`.
- **시험**: 이 검사에 걸리는 입력이 실제로 들어오는 길이 있나.
- **할 일**: 없으면 지운다. 검증은 **경계**에 둔다. 경계는 사용자 입력 · 네트워크 · 파일 · 외부 API처럼 믿을 수 없는 값이 들어오는 자리다.

### 3. 타입을 피하려는 캐스트

- **모습**: `as any`, `as unknown as T`, 이유 없는 `// @ts-ignore` · `// @ts-expect-error`. 다른 언어의 같은 꼴(`# type: ignore`, `@SuppressWarnings("unchecked")`)도 든다.
- **시험**: 타입을 고치거나 좁혀서 같은 일을 할 수 있나.
- **할 일**: 할 수 있으면 고친다. 정말 피할 수 없으면 왜 그런지 주석 한 줄을 붙인다.

### 4. early return으로 풀 깊은 중첩

- **모습**: `if` 안의 `if` 안의 `if`. 본론이 맨 안쪽에 묻혀 있다.
- **할 일**: 조건이 맞지 않으면 먼저 빠져나가게 편다(guard clause, 앞에서 걸러 내는 조건문). 본론을 바깥 들여쓰기로 올린다.

### 5. 주변 코드와 어긋나는 패턴

- **모습**: 같은 파일 · 모듈이 쓰는 이름 짓기, 에러 처리, 헬퍼, 라이브러리와 다른 방식을 새로 들였다. 이미 있는 헬퍼를 두고 같은 일을 하는 함수를 새로 만들었다.
- **시험**: 같은 일을 하는 옆 코드는 어떻게 하나.
- **할 일**: 옆 코드에 맞춘다.

## 통과 기준

다섯 항목마다 diff를 훑고 둘 중 하나로 끝낸다.

- **걸린 곳 0**
- **남긴 곳과 남긴 이유**

보고는 한 줄로 쓴다.

```
deslop: ①주석 0 · ②방어 코드 1 남김 (src/api.ts:30, 외부 응답 검증) · ③캐스트 0 · ④중첩 0 · ⑤패턴 0 — 걷어 낸 뒤 `<증명 명령>` 통과
```
